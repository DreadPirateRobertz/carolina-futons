## 2. Add GSC Property

1. Go to **https://search.google.com/search-console/welcome**
2. Under **URL prefix**, enter: `https://carolinafutons.com`
3. Click **Continue**
4. GSC will offer several verification methods — choose **HTML tag** (meta tag)
5. Copy the token value from the tag: `<meta name="google-site-verification" content="TOKEN_VALUE" />`

### 2.1 Set the verification env var in Vercel

1. Vercel Dashboard → `carolina-futons-web` project → **Settings → Environment Variables**
2. Add variable:
   - **Name:** `GOOGLE_SITE_VERIFICATION`
   - **Value:** `TOKEN_VALUE` (from step 2 above — the content attribute value only, not the full tag)
   - **Environments:** Production (and Preview if desired)
3. Save — trigger a new deploy so the meta tag appears in `<head>`

The `src/lib/seo/webmaster-verification.ts` helper picks this up automatically; `src/app/layout.tsx` injects it via Next.js `metadata.verification`.

### 2.2 Verify

Back in GSC, click **Verify**. GSC will fetch `https://carolinafutons.com` and confirm the meta tag is present. Verification is immediate once the deploy is live.

## 3. Submit the Sitemap

The CFW sitemap is generated by `src/app/sitemap.ts` and served by Next.js at `/sitemap.xml`. It includes:
- 26 static marketing/policy routes
- All PLP category routes (from `SHOP_CATEGORIES`)
- All product PDPs (up to 1,000 from Wix catalog)
- Blog post URLs (up to 100)

### 3.1 Confirm the sitemap is valid

```bash
# On the live site — should return XML with <urlset> root
curl -s https://carolinafutons.com/sitemap.xml | head -20
```

Expected: `<?xml version="1.0" encoding="UTF-8"?><urlset xmlns="...">` with `<url>` entries.

### 3.2 Submit in GSC

1. In GSC, navigate to **Sitemaps** (left sidebar → Indexing → Sitemaps)
2. Under **Add a new sitemap**, enter: `sitemap.xml`
3. Click **Submit**
4. Status should show **Success** with a URL count within a few minutes

## 4. Expected Indexing Timeline

| Milestone | Typical timing |
|---|---|
| Sitemap fetched by Googlebot | Within 24–48h of submission |
| First URLs discovered | 1–3 days |
| Homepage + key PLPs indexed | 3–7 days |
| Full catalog (PDPs, blog) indexed | 2–4 weeks |
| Core Web Vitals data in GSC | 28-day rolling window — first report ~4 weeks post-launch |

A new property with no prior GSC history takes longer to build trust signals. The existing `carolina-futons-web.vercel.app` domain has no indexed value to transfer — expect Googlebot to treat the site as brand-new.

## 5. First 30 Days — What to Monitor

### 5.1 Coverage (Indexing → Pages)

| Signal | What to watch |
|---|---|
| **Indexed** count | Should grow steadily after week 1; plateau when full catalog is crawled |
| **Not indexed → 404** | Any spike here = a PDP or blog route broken post-cutover. Cross-check against redirect-map.md |
| **Not indexed → Crawled, not indexed** | Normal for thin pages (privacy, terms). Abnormal for PLPs or PDPs |
| **Excluded by noindex** | Confirm only dashboard, cart, search, smoke, theme previews are in this bucket |

### 5.2 Sitemaps

- Confirm sitemap status remains **Success** (not **Couldn't fetch** or **Has errors**)
- URL count in sitemap should match roughly: 26 static + N categories + M products + P blog posts

### 5.3 Core Web Vitals (Experience → Core Web Vitals)

Data takes ~28 days to populate. When available, target:
- **LCP** < 2.5s
- **INP** < 200ms
- **CLS** < 0.1

The Lighthouse baseline (see `lighthouse-baseline.md`) was captured pre-launch as a reference.

### 5.4 Search Performance (Performance → Search results)

- After 2–3 weeks, branded queries (`carolina futons`, `carolina futons hendersonville`) should start appearing
- Monitor impressions and clicks for `/shop/futon-frames` — the highest-value organic PLP
- Any 404 surfaced by GSC that maps to a known Wix URL = add a redirect in `next.config.ts`

### 5.5 Manual actions & security

- Check **Security & Manual Actions** tab at cutover + 7 days. Should show "No issues detected."
