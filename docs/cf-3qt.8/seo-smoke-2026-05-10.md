## Sitemap finding (P3, doc-only — not blocking cutover)

`/gift-cards` is **NOT** in `/sitemap.xml`. The page exists and renders correctly (verified by cf-pjdb mobile smoke 06 + cf-ljsy desktop smoke 07 + cf-vtoe tablet smoke 07 + cf-9mm0 dark smoke 07), so the omission is purely a crawler-discovery gap.

128 `<loc>` entries in the sitemap; gift-cards is the one core navigation surface missing.

Suggested follow-up: add `/gift-cards` to whatever script/route generates `sitemap.xml`. Quick win — single static path.

This smoke logs the omission via `console.log` in the test body (visible in the run output above as `[cf-i5sq sitemap omission] /gift-cards: still omitted`) so a future re-run will report `PRESENT (update doc)` once the gap closes, prompting the doc to be updated.

## What this smoke catches

- `/robots.txt` returns wrong status, MIME, or content (Sitemap directive missing → crawlers don't find the URL list; `Disallow: /admin` missing → admin routes get indexed)
- `/sitemap.xml` returns wrong status, isn't valid XML, or omits canonical pages (the 9 enumerated core paths)
- 404 page returns `200 OK` (soft-404 — crawlers penalize)

## Out of scope (separate beads if needed)

- Sitemap **freshness** / `<lastmod>` accuracy — this smoke verifies presence, not staleness
- Sitemap **size** / index sitemaps for products at >1k entries (currently 128 — well under any pagination concern)
- Robots.txt **rate limits** / `Crawl-delay` directives — no Wix-pattern requires those
- Live SERP appearance (Google Search Console) — out of repo's reach
